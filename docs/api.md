# Cloud Controller API reference

Base URL examples

* same machine: `http://localhost:8000`
* from another lab PC: `http://192.168.1.38:8000` (use the server's real LAN IP)

Interactive documentation is generated by FastAPI at `/docs` (Swagger UI) and
`/redoc` **on the controller only**. Restrict these in a real deployment (see
`docs/lan-deployment.md`).

## Error format

Every failure returns the same JSON shape and a meaningful HTTP status:

```json
{
  "error": {
    "code": "not_found",
    "message": "File not found.",
    "details": null
  }
}
```

Validation failures add a `details` array:

```json
{
  "error": {
    "code": "validation_error",
    "message": "Request validation failed.",
    "details": [{"field": "body.password", "message":
      "Value error, Password must contain at least one letter and one digit."}]
  }
}
```

| Code | HTTP | Meaning |
|---|---|---|
| `validation_error` | 422 | Request body/query failed validation |
| `unauthorized` | 401 | Missing, malformed or expired token |
| `forbidden` | 403 | Authenticated but not allowed (non-admin on `/api/admin/*`) |
| `not_found` | 404 | Object missing **or** not owned by the caller |
| `conflict` | 409 | Duplicate username, file-count limit |
| `payload_too_large` | 413 | Upload bigger than the limit, or quota exceeded |
| `rate_limited` | 429 | Too many authentication attempts |
| `storage_unavailable` | 503 | HDFS unreachable or rejected the operation |
| `internal_error` | 500 | Unexpected error (server-side reference id only) |

## Authentication

### `POST /api/auth/register`

Creates an account and immediately returns a token. Rate limited per client IP.
Roles are **never** accepted from the client.

```bash
curl -X POST http://localhost:8000/api/auth/register \
  -H "Content-Type: application/json" \
  -d '{"username":"alice","password":"Passw0rd!"}'
```

`201 Created`

```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIs...",
  "token_type": "bearer",
  "expires_in": 3600,
  "user": {
    "id": "0f1e...", "username": "alice", "role": "user",
    "storage_quota_bytes": 104857600, "is_active": true,
    "created_at": "2026-01-05T09:14:03.221+00:00"
  }
}
```

### `POST /api/auth/login`

```bash
curl -X POST http://localhost:8000/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"alice","password":"Passw0rd!"}'
```

Returns the same payload as register. Wrong credentials always return
`401 {"code":"unauthorized","message":"Invalid username or password."}` —
the response never reveals whether the username exists.

### `GET /api/auth/me`

```bash
curl http://localhost:8000/api/auth/me -H "Authorization: Bearer $TOKEN"
```

## Files

All file routes require `Authorization: Bearer <token>`. Ownership is taken
from the token's subject; **no endpoint accepts a user id from the client**.

### `GET /api/files`

Query parameters: `q` (filename search, ≤100 chars), `sort_by`
(`name|size|date`), `order` (`asc|desc`), `limit` (1–500), `offset`.

```bash
curl "http://localhost:8000/api/files?sort_by=size&order=desc&q=report" \
  -H "Authorization: Bearer $TOKEN"
```

```json
{
  "items": [{
    "id": "d726fd72805440aeae24c13ccbda7977",
    "original_name": "report.pdf",
    "size_bytes": 20480,
    "content_type": "application/pdf",
    "sha256": "9f86d081884c7d659a2feaa0c55ad015...",
    "created_at": "2026-01-05T09:20:11.104+00:00"
  }],
  "total": 1,
  "storage_used_bytes": 20480,
  "storage_quota_bytes": 104857600,
  "sort_by": "size", "order": "desc", "search": "report"
}
```

The HDFS object path is deliberately **not** part of this payload.

### `POST /api/files/upload`

`multipart/form-data` with a single field named `file`.

```bash
curl -X POST http://localhost:8000/api/files/upload \
  -H "Authorization: Bearer $TOKEN" \
  -F "file=@./report.pdf"
```

Pipeline inside the controller:

1. stream the multipart body to a spooled temp file while enforcing
   `MAX_UPLOAD_BYTES` (memory stays bounded at 8 MiB);
2. compute SHA-256;
3. check the per-user file count and quota;
4. sanitise the filename (metadata only), generate a UUID object path;
5. `MKDIRS` the user directory, then `CREATE` the object in HDFS
   (following the NameNode → DataNode 307 redirect);
6. insert the `file_records` row; on failure the HDFS object is removed.

Response `201` with `{"file": {...}, "message": "..."}`.

### `GET /api/files/{file_id}/download`

Streams the object from HDFS (never loading it fully into memory) with
`Content-Disposition: attachment` and an `X-Content-SHA256` header.

```bash
curl -L -o report.pdf \
  -H "Authorization: Bearer $TOKEN" \
  http://localhost:8000/api/files/d726fd72805440aeae24c13ccbda7977/download
curl -s ... | sha256sum   # compare with the metadata value
```

### `DELETE /api/files/{file_id}`

Deletes the HDFS object first, then the metadata row.

* HDFS unreachable → **503**, nothing changed (metadata kept, safe retry).
* HDFS object already missing → metadata is still cleaned up.
* A file owned by somebody else returns **404** (ids are not confirmed).

```bash
curl -X DELETE -H "Authorization: Bearer $TOKEN" \
  http://localhost:8000/api/files/d726fd72805440aeae24c13ccbda7977
```

## Dashboard & profile

### `GET /api/dashboard/stats`

```json
{
  "total_files": 3,
  "storage_used_bytes": 30720,
  "storage_quota_bytes": 104857600,
  "recent_files": [ /* 5 most recent FileResponse objects */ ]
}
```

### `GET /api/auth/me` (profile)

See above — username, role, quota, status, registration timestamp.
There is no separate `/api/profile` route because profile data is exactly the
authenticated user resource (`/api/auth/me`); adding an alias would duplicate
one resource under two URLs.

## Storage status

### `GET /api/health` (public)

```json
{
  "status": "ok",
  "app": "LAN SaaS Cloud Storage",
  "environment": "development",
  "database": "ok",
  "storage": {
    "adapter": "webhdfs",
    "mode_label": "Apache Hadoop HDFS (WebHDFS)",
    "healthy": true,
    "message": "NameNode reachable; configured root exists."
  },
  "max_upload_bytes": 10485760,
  "version": "1.0.0"
}
```

`status` is `ok` only when the database answers **and** the NameNode is
reachable. It is `degraded` when storage is down or the mock adapter is active.

### `GET /api/storage/status` (public, non-sensitive)

Same information as the UI badge needs, **without** the NameNode URL or the
internal HDFS root path.

## Administration

Every route below requires a user whose `role` is `admin` **as stored in the
database**. Ordinary users receive `403 forbidden`, anonymous callers `401`.

| Method | Path | Purpose |
|---|---|---|
| GET | `/api/admin/stats` | user count, admin count, file count, total bytes, HDFS summary |
| GET | `/api/admin/users` | per-user file count and storage usage |
| GET | `/api/admin/hdfs-status` | NameNode URL, health, latency, DataNode liveness (if JMX configured) |
| GET | `/api/admin/audit` | audit events (`limit`, `event_type` filters) |
| PATCH | `/api/admin/users/{id}/role` | promote/demote (cannot demote yourself) |

```bash
curl http://localhost:8000/api/admin/stats -H "Authorization: Bearer $ADMIN_TOKEN"
```

```json
{
  "user_count": 4, "admin_count": 1, "file_count": 3,
  "storage_used_bytes": 30720,
  "hdfs": {"adapter": "webhdfs", "healthy": true,
           "message": "NameNode reachable; configured root exists."},
  "generated_at": "2026-01-05T09:31:44.902+00:00"
}
```

### HDFS status semantics (no faked health)

| Field | Meaning |
|---|---|
| `adapter` | `webhdfs` (real Hadoop) or `mock` (local disk, development only) |
| `healthy` | `true` only if the NameNode answered HTTP 200 for `GETFILESTATUS` on the configured root. `false` when the NameNode is unreachable or the root is missing. `null` for the mock adapter. |
| `datanodes.available` | `null` unless `HDFS_JMX_URL` is configured — WebHDFS itself does **not** expose DataNode liveness |
| `datanodes.live` / `dead` | real counts from the NameNode JMX bean, when configured |

The `mock` adapter reports `healthy: null` and a message that explicitly says
the files are **not** in HDFS. Nothing is ever reported as healthy without a
successful NameNode response.

## Audit events recorded

| Event | Trigger |
|---|---|
| `user_register` | successful registration |
| `login` / `login_failed` / `login_blocked` | authentication attempts |
| `file_upload` | object stored in HDFS and metadata committed |
| `file_download` | stream started |
| `file_download_missing_hdfs` | metadata exists but the object is gone |
| `file_delete` | object and metadata removed |
| `admin_role_change` | role promotion/demotion |

Audit rows store who/what/when/from-where and a short detail string such as
`file_id=... size=...`. Passwords, hashes, tokens and file contents are never
stored — this is asserted by the test suite.
